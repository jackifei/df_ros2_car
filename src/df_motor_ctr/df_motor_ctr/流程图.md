# wheel_dir_pwm.py 执行流程图

本文件说明 `wheel_dir_pwm.py` 中节点初始化、IMU 接收、转向指令处理以及 PID 航向保持的执行顺序。

## 1. 节点初始化与事件分发

```mermaid
flowchart TD
    A["main()"] --> B["JoyToServoNode.__init__()"]
    B --> C["声明并读取串口、IMU、PID 参数"]
    B --> D["打开串口 serial.Serial()"]
    B --> E["创建订阅 /wheel_control/dir -> dir_callback"]
    B --> F["创建订阅 /imu/data -> imu_callback"]
    B --> G["创建发布 /df_dir_rt"]

    E -. "收到转向指令" .-> H["dir_callback(msg)"]
    F -. "收到 IMU 数据" .-> I["imu_callback(msg)"]
```

## 2. 收到 IMU 数据后的执行流程

```mermaid
flowchart TD
    A["imu_callback(msg)"] --> B["调用 _yaw_from_quaternion(qx, qy, qz, qw)"]
    B --> C["检查四元数是否有效：isfinite 且 norm > 1e-6"]
    C --> D{"四元数有效？"}
    D -- "是" --> E["归一化四元数并计算 yaw = atan2(...)"]
    E --> F["更新 _current_yaw"]
    F --> G["设置 _imu_received = True"]
    G --> H["本次回调结束"]
    D -- "否" --> I["忽略本帧数据"]
    I --> J["保持上一帧 _current_yaw 不变"]
    J --> H
```

## 3. 收到前轮转向指令后的执行流程

```mermaid
flowchart TD
    A["dir_callback(msg)"] --> B["base_angle = msg.data / pi * 180"]
    B --> C["heading_correction = _compute_heading_correction(msg.data)"]
    C --> D["angle = base_angle + heading_correction"]
    D --> E["cmd = f'{angle:.1f}\\n'"]
    E --> F["serial.write(cmd)"]
    F --> G["publish('/df_dir_rt', angle)"]
    G --> H["本次回调结束"]

    F -. "串口写入异常" .-> I["记录日志"]
    I --> H
```

## 4. `_compute_heading_correction()` 内部详细流程

```mermaid
flowchart TD
    A["_compute_heading_correction(steering_rad)"] --> B{"总开关开启且已收到 IMU？"}

    B -- "否" --> C["清空参考航向、直行计时和 PID 状态"]
    C --> D["return 0.0"]

    B -- "是" --> E{"abs(steering_rad) <= 0.1 rad？"}

    E -- "否：转弯" --> F["不启用 PID，不使用历史 PID 数据"]
    F --> G["清空参考航向、直行计时，调用 _reset_heading_pid()"]
    G --> H["return 0.0"]

    E -- "是：直行" --> I{"当前已经处于航向保持 active？"}

    I -- "否" --> J["等待 heading_settle_time 让 yaw 稳定"]
    J --> K{"稳定时间已到？"}
    K -- "否" --> L["return 0.0"]
    K -- "是" --> M["锁定当前 _current_yaw 为参考航向"]
    M --> N["active = True，调用 _reset_heading_pid()"]
    N --> O["记录本次控制时间"]
    O --> P["return 0.0"]

    I -- "是" --> Q["计算 dt，并限制最大 0.5 秒"]
    Q --> R["yaw_error = _normalize_angle(current_yaw - reference)"]
    R --> S["误差转角度，更新积分项并限幅"]
    S --> T["计算微分项"]
    T --> U["PID 输出 = kp*P + ki*I + kd*D"]
    U --> V["correction = heading_correction_sign * PID 输出"]
    V --> W["限制 correction 在 ±heading_correction_limit_deg"]
    W --> X["return correction"]
```

## 5. 方法调用关系表

| 触发事件 | 首先执行 | 其次执行 | 说明 |
| --- | --- | --- | --- |
| 收到 IMU 数据 | `imu_callback()` | `_yaw_from_quaternion()` | 从四元数得到 yaw，更新 `_current_yaw` |
| 收到转向指令 | `dir_callback()` | `_compute_heading_correction()` | 计算是否需要叠加 PID 修正 |
| 计算相对偏航 | `_compute_heading_correction()` | `_normalize_angle()` | 把 yaw 误差限制到 `[-pi, pi]` |
| 退出直行/进入转弯 | `_compute_heading_correction()` | `_reset_heading_pid()` | 清除积分、微分和上次时间 |
| 发送舵机指令 | `dir_callback()` | `serial.write()` | 把最终角度发送给舵机 |
| 发布实时转向角 | `dir_callback()` | `pub.publish()` | 发布 `/df_dir_rt` |

## 6. 转弯后再次直行的处理

1. 转弯时：`_heading_control_active` 设为 `False`，参考航向和 PID 历史数据被清空。
2. 再次进入直行时：不会立即锁定参考航向。
3. 先等待 `heading_settle_time` 秒，让车头 yaw 稳定。
4. 稳定后锁定当前 yaw 作为新的参考航向，并重新开始 PID。

这样做的目的是避免把转弯末段的瞬时偏航锁成参考方向。
